01Overview

InterviewCopilot listens to system audio on Windows. It streams the audio to a Gemini Live model. Short text replies appear on a stealth HUD. The app captures no screen pixels. It uses no microphone by default. An optional dual mode adds the microphone.

Design principles

  • Never crash, never hang the UI. Device APIs can block. Every hardware query runs with a hard timeout.
  • Drop, do not buffer. Audio queues stay bounded. Full queues drop the oldest frame.
  • Text in, text out. The Live session uses AUDIO modality with server-side transcription. Pure TEXT sessions fail server-side with code 1007 (verified Oct 2026). The HUD shows text only. Audio never plays.
  • PySide6 only. One Qt binding keeps the exe lean. The build excludes PyQt5, PyQt6, and PySide2. Dual bindings would bloat the exe to about 500 MB.
  • Stealth by default. The HUD sets WDA_EXCLUDEFROMCAPTURE. Screenshots and screen shares miss it. Global hotkeys hide and show it.

03How it works

The pipeline runs in a straight line. One loop exists: the Live session recycle.

  1. Startup. main.main() parses --diag and --auto, loads config.json (defaults merged), and either shows settings or calls run_hud_session().
  2. Enrich. _enrich_instruction() appends the speaker protocol, the difficulty prompt (EASY / MEDIUM / HARD / EXPERT), candidate context (role / company), and knowledge-base content when enabled. The function is idempotent. You can call it twice.
  3. Capture. AudioEngine.start() spawns two daemon threads: audio-loopback (WASAPI via soundcard) and audio-mixer. Each loopback chunk resamples to 16 kHz mono and lands in a rolling buffer.
  4. Mix and classify. The mixer takes the latest loopback chunk (plus mic in dual mode), pads or truncates to CHUNK_SAMPLES = 1024 (about 64 ms), mixes with numpy, computes abs-mean energies, and classifies the speaker (interviewer / candidate / both / silence) with a 2-frame debounce.
  5. Queue. Mixed PCM (16-bit, 16 kHz) goes to output_queue. Speaker markers ([SPEAKER: …]) go to speaker_queue. Both queues are bounded. Overflow drops the oldest item.
  6. Produce. _produce() drains speaker markers first, then audio frames. It sends them as audio/pcm;rate=16000 realtime input.
  7. Model. Gemini Live (AUDIO modality, input/output transcription, automatic activity detection with 80 ms prefix padding and 150 ms silence duration, TURN_INCLUDES_ALL_INPUT) hears the turns and answers in audio. The client transcribes the answer to text. The HUD stays text-only.
  8. Consume. _consume() reads the session, handles text deltas and the optional web_search function tool, and calls on_text.
  9. Render. Each signal crosses back to the Qt thread through hud.text_signal (QueuedConnection). The HUD appends it as markdown-lite HTML. Status crosses through hud.status_signal.
  10. Record. When enabled, the app appends model text to transcripts/session_<timestamp>.md without blocking the event loop (asyncio.to_thread).
  11. Recycle. Every 10 minutes (configurable, min 120 s) the session recycles to bound server-side context drift. The outer loop reconnects with exponential backoff (2 s × 1.6, capped at 30 s) and a fallback model chain.

The self-test hello

On first connect the client asks the model to reply with exactly audio pipeline OK. It sends the hello through send_realtime_input(text=…), then falls back to send_client_content. The reply arrives through the normal consume path. This proves the text path works in a silent room. The client tries up to 3 times. When the session dies within 10 s of the hello, the next session retries it.

Why two queues?

output_queue carries mixed PCM. speaker_queue carries out-of-band text hints about who speaks. The producer drains markers first. The model always knows the current speaker before the audio frame that follows. No ordering hacks. No timestamp juggling.

05Data-flow sequence

Audio budget

  • 16,000 Hz · mono · int16. Each output_queue frame holds exactly 1024 × 2 = 2048 bytes (about 64 ms of audio).
  • Queue depth caps latency. 200 frames equal about 12.8 s of worst-case backlog. Drop-oldest keeps real depth at 1–2 frames.
  • Hangover = 2 frames. Two trailing-silence frames (~128 ms) follow speech. Turn boundaries stay intact. VAD debounce = 2 frames.
  • Endpointing. Prefix padding = 80 ms. Silence wait = 150 ms. The server uses these for turn detection.
  • Reply cap. max_output_tokens = 160. Long answers arrive late. Brevity buys latency.

07Config schema

config_manager.DEFAULT_CONFIG is the single source of truth. Unknown keys in config.json stay preserved. Missing keys fall back to defaults. Corrupt JSON falls back to defaults. Writes stay atomic (.tmp + os.replace) under a process-wide RLock.

Path logic (get_config_path())

  • Frozen exe (sys.frozen): <exe-dir>/config.json. The user edits this file and ships it next to the exe.
  • Source run: <script-dir>/config.json.
  • First run with no file: the app returns DEFAULT_CONFIG in memory. The file materializes on the first save_config() (for example, settings dialog "Save").

What build_exe.py does (audited)

  1. Resolves paths from __file__, not cwd. The script works from any working directory. main.py, app_icon.ico, and version_info.txt use absolute paths.
  2. Verifies the entry point exists. Exits with code 2 and a plain-English hint when it does not. Verifies PyInstaller imports under this interpreter. Exits 2 with the exact pip install command when it does not.
  3. Writes version_info.txt from the embedded VERSION_INFO_TXT (1.0.0, CompanyName = InterviewCopilot — never impersonates a system binary) and passes --version-file on Windows.
  4. Passes hidden imports for every local module plus the native or optional deps PyInstaller misses (PySide6.*, shiboken6, sounddevice, soundcard, google.genai(.types), httpx, pypdf, pynput.*_win32), plus --collect-all for the audio libs and the google package.
  5. Excludes the other Qt bindings (PySide2, shiboken2, PyQt5, PyQt6(.QtWebEngine)) — never PySide6. App code imports PySide6 exclusively (verified by grep; the only "PyQt" mentions are comments and excludes).
  6. Passes --icon only when app_icon.ico exists (present, ~17 KB). Warns instead of silently skipping when it is missing.
  7. Reports the correct output path per mode (onedir → inside the folder, onefile → the single exe) and reminds you to ship config.json alongside.

Spec & installer artifacts

InterviewCopilot.spec is generated, not edited. PyInstaller rewrites it in the project root on every build, and its absolute paths tie it to one machine. The repo keeps it only as a record of the last build settings (onedir, windowed, console=False, icon plus version file). Compile installer.iss manually with Inno Setup 6 after a build. Bump its MyAppVersion 1.0.0 in step with build_exe.VERSION_INFO_TXT and version_info.txt.

config.json shipping rules

  • Never bake a real key into the exe image. config.json travels next to the exe (onedir folder or beside the onefile exe).
  • First run without it: defaults apply. The file materializes on Save.
  • It is .gitignored (with .env variants). Redact before you post logs.

11Testing strategy

12Security notes

API key handling

  • The key lives only in config.json (plaintext, by necessity for a local desktop app). It is .gitignored and never embedded in the exe.
  • Logs never print it. _mask_key() shows AIza…90 (len=39)-shaped fragments. _log_launch_diagnostics() reports only the AIza prefix check. Transcripts and the HUD never contain the key.
  • The settings key field uses Password echo-mode with an opt-in Show toggle. Rotate the key by editing config.json (or the dialog), then Save.
  • Atomic save (.tmp + os.replace) avoids half-written files when the process dies mid-write.

Stealth posture

  • WDA_EXCLUDEFROMCAPTURE keeps the HUD out of screenshots and screen shares (needs Win10 2004+ / build 19041+). A pill in the HUD shows the live on/off state.
  • Click-through mode lets clicks pass through the HUD. Ctrl+Alt+H hides it instantly. This is user convenience, not OS-level invisibility. The process is a normal Windows app. It shows up in Task Manager and the taskbar.
  • Audio-only input: the app captures no screen pixels, takes no screenshots, and sends no pixels. The model hears computer sound (plus mic in dual mode) and returns text.
  • No telemetry. The app makes exactly two network calls: the Gemini Live session (key supplied) and the DuckDuckGo search HTML endpoint when the web tool is enabled.
Scope reminder. Real-time assistance in live interviews may violate the policies of the interviewer or event organizer. Stealth features reduce casual visibility. They do not make the activity comply with any given policy.
